# 编程 Agent 联网搜索源码调研

## 结论

通用编程 Agent 通常不把“联网”做成一个无边界浏览器，而是拆成结构化搜索、受控网页抓取和可选浏览器自动化三层。搜索结果作为普通 tool result 回到 Agent 循环，必须带来源 URL、有输出上限，并受权限、取消和网络策略约束。

## DexCode 建议

最短可交付路径是先实现第一方 `web_search`，不同时实现 `web_fetch` 和浏览器。

1. 在 tool registry 中定义稳定 schema：`query`、`allowed_domains`、`blocked_domains`、`max_results`，返回 `title/url/snippet/published_at`。
2. 在 registry 后放一个可替换 `WebSearchProvider`，MVP 接 Brave/Tavily/Exa 之一；API key 只在 Runtime 配置层，不暴露给模型。
3. 将它标记为 `external` 副作用，因为 query 会离开本机；复用现有 approval fingerprint、取消和 tool-result 错误封装。
4. 限制单次结果数、snippet 长度和总字节；保留 URL，工具结果中提醒 Agent 使用 Markdown 链接引用。
5. 补齐 registry/schema → host/executor → policy/approval → protocol/replay → conversation presentation → settings 与少量主链测试。

DexCode 已有合适的落点：权威 registry 会投影模型 schema，tool host 集中执行和统计，`external` 已进入批准模型，MCP 也能作为零代码短期验证通道。
