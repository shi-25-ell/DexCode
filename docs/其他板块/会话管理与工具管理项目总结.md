# 会话管理与工具管理项目总结

## 优化目标

根据系统演进设计文档 §3.1"对话与工具管理"的要求，实现 Agent 产品化的基本需求——用户可以在 Web 应用中完整管理对话（会话）和工具，同时打通外部 MCP 工具的运行时注册与发现。

## 已实现能力

### 1. 会话管理

修改文件：

- `packages/shared/types.ts` — Session 类型新增 `title`、`archived` 字段，新增 `SessionMeta` 类型
- `packages/session-store/index.ts` — 新增 4 个方法，增强 2 个方法
- `apps/runtime/server.ts` — 新增 4 个 API 端点
- `apps/web/app.ts` — 会话下拉面板重构
- `apps/web/styles.css` — 新增会话操作按钮样式

#### 数据模型

```typescript
type Session = {
  // ...原有字段
  title?: string;          // 会话标题
  archived?: boolean;      // 是否归档
};

type SessionMeta = {
  title?: string;
  archived?: boolean;
};
```

#### 新增 API

| 方法 | 路径 | 功能 |
|---|---|---|
| DELETE | `/api/session/:id` | 删除会话及其文件 |
| PATCH | `/api/session/:id` | 重命名 / 归档 |
| GET | `/api/session/:id/export` | 导出完整会话 JSON |
| GET | `/api/sessions/search?q=` | 按标题和最后消息搜索 |

#### 关键实现细节

- **自动标题**：`appendMessages` 检测到首条用户消息时，自动截取前 30 字符作为会话标题
- **删除联动**：删除当前会话时自动创建新会话，删除非当前会话时仅移除文件
- **UI 富卡片**：每个会话项展示短 ID、标题、时间、消息数、任务数、归档标记，内嵌重命名/归档/导出/删除四按钮

#### 增强能力

- `listSessions` 返回结构增加 `title`、`archived`、`messageCount` 字段
- 删除使用 `fs.rm` 以兼容新版 Node.js

### 2. 工具管理（Tool Registry）

修改文件：

- `packages/tool-gateway/index.ts` — 新增 ToolRegistry 与统计代理
- `apps/runtime/server.ts` — 新增 3 个 API 端点
- `apps/web/index.html` — 新增工具管理面板
- `apps/web/app.ts` — 工具卡片渲染与交互
- `apps/web/styles.css` — 新增工具卡片样式

#### 架构设计

```
wrapWithStats(名称, 描述, 原函数) → 统计代理函数
    │
    ▼
ToolRecord（Map<名称, { 调用次数, 成功次数, 平均耗时, 启用状态 }>）
    │
    ▼
registry.getAllToolInfos() → GET /api/tools → 前端工具管理面板
registry.setToolEnabled()  → PATCH /api/tools/:name
registry.testTool()        → POST /api/tools/:name/test
```

#### 新增 API

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/api/tools` | 列出全部工具（含统计字段） |
| PATCH | `/api/tools/:name` | 启用 / 禁用单个工具 |
| POST | `/api/tools/:name/test` | 测试工具调用 |

#### 统计字段

每个工具记录以下实时指标：

| 字段 | 说明 |
|---|---|
| `callCount` | 累计调用次数 |
| `successCount` | 成功次数 |
| `avgDurationMs` | 指数移动平均耗时 |
| `lastCalledAt` | 最近调用时间 |
| `enabled` | 启用状态开关 |

#### 统计代理机制

`wrapWithStats` 使用 rest 参数保留原始函数签名。当前 10 个内置编程工具（`find`、`ls`、`list_workspace`、`read_file`、`grep`、`run_command`、`patch_file`、`write_file`、`read_command_output`、`stop_command`）均由权威 registry 注册，再通过统一代理记录调用统计。

#### 前端面板

工具管理面板集成在主页面右侧日志面板中，每个工具以卡片展示：
- 工具名称 + 来源标签（内置/外部）
- 功能描述
- 累计调用次数、成功率、平均耗时
- 启用/禁用开关

### 3. 外部 MCP 服务器管理

修改文件：

- `packages/mcp-client/index.ts` — 惰性 stdio transport，动态 `addServer`/`removeServer`
- `apps/runtime/server.ts` — 新增 3 个运行时管理 API
- `apps/web/mcp-config.ts` — 前后端同步、删除按钮
- `apps/web/tsconfig.build.json` — 修复 mcp-config.ts 未编译问题

#### 问题发现

早期版本中外部 MCP 存在以下问题：

- **启动崩溃**：`stdio` transport 在服务器启动时立刻 `spawn` 子进程，命令不存在时直接 crash
- **前后端不连通**：前端 MCP 配置保存在 `localStorage`，后端从 `EXTERNAL_MCP_SERVERS` 环境变量读取 —— 两边数据源不同
- **无法运行时管理**：无 API 端点支持动态增删 MCP 服务器

#### 解决方案

| 问题 | 解决方案 |
|---|---|
| stdio 启动崩溃 | 改为惰性初始化，仅在首次 `listTools` 或 `callTool` 时才 `spawn` |
| 前后端不连通 | 新增 `POST /api/external-mcp/servers` API；前端保存时自动同步到后端；`localStorage` 为主数据源 |
| 无法运行时管理 | 新增 `addServer`/`removeServer`/`listServers` 方法 + 3 个管理 API |
| Windows spawn 失败 | 使用 `shell: true` 兼容 `.cmd` 命令；超时从 30s 延长至 120s |
| 配置无法删除 | MCP 卡片新增删除按钮 |

#### 新增 API

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/api/external-mcp/servers` | 注册 / 同步服务器列表 |
| GET | `/api/external-mcp/servers` | 列出已注册服务器 |
| DELETE | `/api/external-mcp/servers/:name` | 移除指定服务器 |

#### 验证

使用 `@modelcontextprotocol/server-filesystem` 进行端到端测试：
- MCP 配置保存后自动同步到后端
- `GET /api/external-mcp/tools` 返回 14 个文件系统工具（`read_text_file`、`write_file`、`edit_file`、`list_directory`、`search_files` 等）
- 工具管理面板同时展示 9 个内置工具 + 14 个外部 MCP 工具
- Agent 对话中可正常调用 `mcp__filesystem__*` 工具
